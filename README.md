# ระบบจับคู่เงินทดลองจ่าย (Yushi Systems)

เว็บแอปสำหรับอัปโหลด **รายงานแยกประเภททั่วไป** (บัญชีเงินทดลองจ่าย) ในรูปแบบ Excel หรือ PDF
ระบบจะจับคู่รายการจ่ายเงินกับรายการเคลียร์โดยอัตโนมัติ แล้วออกรายงานเฉพาะ **รายการที่ยังไม่มีคู่**
พร้อม **ยอดคงเหลือที่คำนวณใหม่** เป็นไฟล์ Excel หรือ PDF ในรูปแบบเดียวกับรายงานต้นฉบับ

---

## หลักการจับคู่

ในรายงาน รายการหลักจะลงยอดที่ช่อง **เดบิต** พร้อมเลขใบสำคัญ (เช่น `PV6901011`)
เมื่อเคลียร์แล้วจะมีอีกรายการลงที่ช่อง **เครดิต** ด้วยยอดเท่ากัน โดยคำอธิบายอ้างถึงเลขใบสำคัญนั้น
เช่น `เคลีย PV6901011 ฺBSB SO6812009 บจ.ครูเกอร์ฯ`

ระบบจับคู่ด้วยการ "ตัดยอด" (allocation) ทีละเกณฑ์ เข้มงวดที่สุดก่อน — รายการหนึ่งจึงถูกเคลียร์
บางส่วนหรือหลายครั้งได้:

| ลำดับ | เกณฑ์ | ความมั่นใจ | ค่าเริ่มต้น |
|---|---|---|---|
| 1 | อ้างเลขใบสำคัญ + ยอดตรงกันพอดี | 100% | เปิด |
| 2 | อ้างเลขใบสำคัญ (เคลียร์บางส่วน / ยอดไม่ตรงพอดี) | 80% | เปิด |
| 3 | อ้างเลขงาน SO/PO เดียวกัน + ยอดตรงกันพอดี | 70% | เปิด |
| 4 | ยอดตรงกันพอดี + คำอธิบายอ้างถึงคู่ค้ารายเดียวกัน | 60% | เปิด |
| 5 | อ้างเลขงาน SO/PO เดียวกัน (ยอดไม่ตรงพอดี) | 45% | ปิด |
| 6 | ยอดเงินตรงกันพอดี และมีผู้เข้าคู่เพียงรายเดียว | 30% | ปิด |

เกณฑ์ทั่วไปเดินสองรอบเสมอ — **รอบแรกรับเฉพาะคู่ที่ลำดับวันที่ถูกต้อง** (รายการเคลียร์ต้องเกิดหลังหรือ
วันเดียวกับรายการจ่ายเงิน) รอบสองจึงยอมให้ย้อนวันได้ เพื่อกันกรณีพิมพ์เลขใบสำคัญผิดไปคว้ารายการ
ที่ยังไม่เกิดขึ้น ณ วันที่เคลียร์

**เกณฑ์ที่ 4 เดินรอบเดียว** คือบังคับลำดับวันที่เสมอ ใช้รับกรณีจ่ายชำระหนี้ (ใบสำคัญ PS) ที่คำอธิบาย
เขียนแต่ชื่อผู้ขาย ไม่ได้อ้างเลขใบสำคัญหรือเลขงาน เช่น `25%ดราก้อน งานติดตั้งปรับอุณภูมิ...`
คู่กับ `ชำระหนี้ให้ บริษัท ดราก้อน แอร์ ดักท์ จำกัด` การเทียบชื่อคู่ค้าทำโดยตัดเลขเอกสาร ตัวเลข
และคำที่โผล่ทุกบรรทัด (เงินทดลอง / ชำระหนี้ให้ / เคลีย / บริษัท / หจก / จำกัด …) ออกก่อน
แล้วดูว่ามีสตริงย่อยภาษาไทยยาวอย่างน้อย 5 ตัวอักษรตรงกันหรือไม่ — ใช้สตริงย่อยแทนการตัดคำ
เพราะคำอธิบายเขียนติดกันและสะกดไม่เหมือนกันเป๊ะ (`หจก.มั่นคงสตีล` กับ `หจก. ค้ามั่นคงสตีล`)
ชื่อคู่ค้าเป็นหลักฐานที่อ่อนกว่าเลขเอกสาร จึงไม่ยอมให้ย้อนวัน ไม่งั้นจะไปคว้ารายการของคู่ค้า
รายเดียวกันที่เป็นคนละงานคนละเดือน

เกณฑ์ที่ 5 และ 6 ปิดไว้ตามค่าเริ่มต้นเพราะเดาจากยอดเงินอย่างเดียว หน้าเว็บใช้ค่าเริ่มต้นเสมอ
ถ้าต้องการเปิดเพิ่มให้ส่ง `options` ผ่าน API (`POST /api/upload` หรือ `POST /api/jobs/:id/rematch`)

### การตรวจสอบความถูกต้อง

การจับคู่เป็นการหักล้างเดบิตกับเครดิตที่เท่ากัน **ยอดคงเหลือใหม่จึงต้องเท่ากับยอดคงเหลือท้ายรายงาน
ต้นฉบับเสมอ ไม่ว่าจะเปิดเกณฑ์ใด** ระบบตรวจข้อนี้ให้อัตโนมัติและแสดงผลบนหน้าเว็บ
ถ้าไม่ตรงแปลว่าไฟล์ต้นฉบับมีปัญหา

## การอ่านไฟล์

**Excel (.xlsx)** — ค้นหาแถวหัวตารางจากชื่อคอลัมน์ (`ใบสำคัญ` / `คำอธิบาย` / `เดบิต` / `เครดิต`)
จึงไม่ผูกกับตำแหน่งคอลัมน์ตายตัว รองรับการเว้นวันที่ว่างเมื่อซ้ำกับแถวก่อนหน้า และตัดแถวสรุปท้ายรายงานออก

**PDF** — รายงานถูกพิมพ์เป็นตารางตัวอักษรความกว้างคงที่ (monospace) ระบบจึงประกอบบรรทัดกลับมาเป็น
กริดตามตำแหน่ง x แล้วสอบเทียบตำแหน่งคอลัมน์ตัวเลขจากข้อมูลจริง (ตัวเลขจัดชิดขวา ตำแหน่งสิ้นสุด
ของแต่ละคอลัมน์จึงคงที่) ซึ่งแม่นกว่าการอ่านตำแหน่งจากป้ายหัวตาราง

PDF ที่ออกจากโปรแกรมบัญชีนี้ฝังฟอนต์ที่วางสระและวรรณยุกต์ไทยไว้ใน Private Use Area (U+F700–U+F71A)
แทนรหัส Unicode มาตรฐาน `src/parsers/pdf.js` มีตารางแปลงกลับที่สอบเทียบจากไฟล์ตัวอย่างจริงโดย
เทียบข้อความ PDF กับ Excel แถวต่อแถว

> ผลการทดสอบกับไฟล์ตัวอย่าง: อ่านจาก Excel และ PDF ได้ **486 รายการเท่ากัน เลขใบสำคัญและจำนวนเงิน
> ตรงกันทุกแถว** (ต่างกัน 0 แถว) ข้อจำกัดของ PDF คือคำอธิบายถูกตัดตามความกว้างคอลัมน์ของรายงานต้นฉบับ
> หากต้องการคำอธิบายเต็มควรใช้ไฟล์ Excel

## รูปแบบไฟล์ที่ออก

ไฟล์ที่ดาวน์โหลดถูกทำให้ **หน้าตาและการจัดวางเหมือนรายงานต้นฉบับตามประเภทไฟล์** โดยวัดค่าจริง
จากไฟล์ตัวอย่างมาใช้ทั้งหมด ต่างกันแค่แสดงเฉพาะรายการที่ยังไม่มีคู่และยอดคงเหลือที่คำนวณใหม่

**Excel** — ความกว้างคอลัมน์ A–H, ฟอนต์ Tahoma 11 กับรูปแบบบัญชี `_-* #,##0.00_-;...`,
วันที่เป็นวันที่จริงปี พ.ศ. รูปแบบ `mm-dd-yy`, หัวรายงานสี่บรรทัดแรกพิมพ์ซ้ำจากไฟล์ต้นฉบับทั้งบรรทัด,
ปิดท้ายด้วยแถว `รวม` / `รวมทั้งสิ้น` และหมายเหตุช่อง "สถานะ" เหมือนต้นฉบับ

**PDF** — A4 แนวตั้ง บรรทัดละ 18 pt หน้าละ 39 บรรทัด ตำแหน่งคอลัมน์ตามแกน x เดียวกับต้นฉบับ
มีเส้นประคั่น หัวรายงานซ้ำทุกหน้าพร้อม `หน้า : n` และ `(ต่อ)` ตั้งแต่หน้าสอง ปิดท้ายด้วย
`รวม` / `รวมทั้งสิ้น` / หมายเหตุ / `>>>>  จบรายงาน  <<<<`

> ต้นฉบับใช้ฟอนต์ความกว้างคงที่ขนาด 12 ส่วนระบบนี้ใช้ Sarabun ซึ่งเป็นฟอนต์สัดส่วน
> จึงตั้งขนาด 9.5 เพื่อให้ตัวอักษรลงตำแหน่งคอลัมน์เดิมได้พอดีโดยไม่ชนกัน

ทั้งสองแบบเติมท้ายด้วยบล็อก **สรุปการจับคู่** (จำนวนคู่ที่จับได้ ยอดค้างแต่ละด้าน และยอดคงเหลือ
เทียบกับต้นฉบับ) ซึ่งเป็นส่วนเดียวที่ไม่มีในรายงานต้นฉบับ

## ติดตั้งบนเครื่องพัฒนา

```bash
npm install
cp .env.example .env       # แล้วแก้ค่าให้ตรงกับเครื่อง
npm start                  # เปิดที่ http://localhost:3000
```

### ทดสอบ

```bash
# ทดสอบครบวงจรโดยไม่ต้องใช้เซิร์ฟเวอร์/ฐานข้อมูล — ให้ทั้ง Excel และ PDF เพื่อเทียบผลลัพธ์กัน
node scripts/smoke.js "path/to/report.xlsx" "path/to/report.pdf"

# ทดสอบ API ผ่าน HTTP จริง (ต้องรันเซิร์ฟเวอร์ไว้ก่อน)
node scripts/api-test.js http://127.0.0.1:3000 "path/to/report.xlsx"
```

ไฟล์ผลลัพธ์ที่สร้างระหว่างทดสอบอยู่ในโฟลเดอร์ `out/` (ไม่ถูก commit)

## Deploy บน Plesk

### 1. เตรียมฐานข้อมูล

ที่ **Databases → Add Database** สร้างฐานข้อมูลและผู้ใช้:

- Database name: `leaf_finance`
- Database user: `leaf_finance`
- Character set: **utf8mb4** (สำคัญ — ต้องรองรับภาษาไทย)

> ชื่อฐานข้อมูลจริงบน Plesk อาจมี prefix ของบัญชีนำหน้า ให้ใส่ชื่อที่เห็นในหน้า Databases
> ลงใน `DB_NAME` ของไฟล์ `.env`

### 2. อัปโหลดโค้ด

```bash
git clone https://github.com/neonuafah/finance_yushi.git
```

หรืออัปโหลดผ่าน File Manager แล้ววางไว้ที่ Application Root เช่น `/httpdocs/finance`

### 3. ตั้งค่า Node.js ใน Plesk

ที่ **Websites & Domains → Node.js**:

| ช่อง | ค่า |
|---|---|
| Node.js version | 18 หรือใหม่กว่า |
| Application Mode | production |
| Application Root | โฟลเดอร์ที่วางโค้ด เช่น `/httpdocs/finance` |
| Application URL | URL ที่ต้องการ เช่น `https://example.com/finance` |
| Application Startup File | `server.js` |

กด **NPM Install** เพื่อติดตั้ง dependencies

### 4. สร้างไฟล์ `.env`

คัดลอกจาก `.env.example` ไปไว้ที่ Application Root:

```ini
NODE_ENV=production
PORT=3000

# ตั้งเมื่อแอปอยู่ใต้ path ย่อย (เว้นว่างถ้าอยู่ที่ราก)
BASE_PATH=/finance

DB_ENABLED=true
DB_HOST=localhost
DB_PORT=3306
DB_USER=leaf_finance
DB_PASSWORD=รหัสผ่านฐานข้อมูล
DB_NAME=leaf_finance

MAX_UPLOAD_MB=25
RESULT_TTL_MINUTES=120
```

> `.env` อยู่ใน `.gitignore` แล้ว **อย่า commit รหัสผ่านเข้า git**
> ถ้าตั้งค่าผ่าน **Custom environment variables** ในหน้า Node.js ของ Plesk แทนก็ได้ (ปลอดภัยกว่า)

### 5. สร้างตาราง

เซิร์ฟเวอร์สร้างตารางให้อัตโนมัติตอนเริ่มทำงาน หรือสั่งเองผ่าน SSH:

```bash
npm run db:init
```

### 6. Restart App

กด **Restart App** ในหน้า Node.js แล้วเปิด Application URL

ตรวจสถานะได้ที่ `<URL>/api/health` — ควรได้ `{"ok":true,"db":{"available":true,...}}`

### ข้อควรรู้

- **ถ้าฐานข้อมูลใช้ไม่ได้ ระบบยังทำงานได้ตามปกติ** เพียงแต่ไม่บันทึกประวัติ หน้าเว็บจะแจ้งเตือนไว้
- ไฟล์ที่อัปโหลด **ไม่ถูกเขียนลงดิสก์** ประมวลผลในหน่วยความจำแล้วทิ้งทันที
- ผลลัพธ์ถูกเก็บตาม `RESULT_TTL_MINUTES` เพื่อให้ดาวน์โหลดซ้ำและปรับเกณฑ์ได้โดยไม่ต้องอัปโหลดใหม่
  — หลังจากนั้นต้องอัปโหลดไฟล์อีกครั้ง เก็บไว้ทั้งในหน่วยความจำและเป็นไฟล์ JSON ใน `tmp/jobs/`
  เพราะ Passenger รันแอปได้หลาย process พร้อมกัน คำขอดาวน์โหลดจึงอาจไปตกที่ process
  ที่ไม่ได้เป็นคนประมวลผลไฟล์ ระบบล้างไฟล์ที่หมดอายุให้เองทุกครั้งที่มีงานใหม่เข้ามา
- ถ้า Plesk ใช้ Passenger แล้วอัปโหลดไฟล์ใหญ่ไม่ผ่าน ให้เพิ่ม `client_max_body_size 30m;`
  ใน **Apache & nginx Settings → Additional nginx directives**

## โครงสร้างโปรเจกต์

```
server.js                  จุดเริ่มต้น Express + graceful shutdown
src/
  config.js                อ่านค่าจาก .env
  domain.js                โมเดลแถวรายการ, แปลงจำนวนเงิน/วันที่ พ.ศ., ดึงเลขเอกสาร
  matcher.js               อัลกอริทึมจับคู่แบบตัดยอด + คำนวณยอดคงเหลือใหม่
  store.js                 เก็บผลลัพธ์ชั่วคราวในหน่วยความจำ
  db.js                    MySQL pool, migrate, บันทึกประวัติ (ล้มเหลวแล้วไม่ล้มระบบ)
  schema.sql               ตาราง jobs / entries / matches
  parsers/excel.js         อ่าน .xlsx (ค้นหาหัวตารางอัตโนมัติ)
  parsers/pdf.js           อ่าน .pdf (สร้างกริด monospace + แปลง Thai PUA)
  exporters/report.js      แบบจำลองรายงานที่ตัวออกไฟล์ทั้งสองใช้ร่วมกัน
  exporters/excel.js       ออก .xlsx
  exporters/pdf.js         ออก .pdf (ฟอนต์ Sarabun)
  routes/api.js            REST API
public/                    หน้าเว็บ (ไม่มี build step)
assets/fonts/              Sarabun (SIL Open Font License)
scripts/                   init-db, smoke, api-test
```

## API

| Method | Path | คำอธิบาย |
|---|---|---|
| `GET` | `/api/health` | สถานะระบบและฐานข้อมูล |
| `GET` | `/api/strategies` | รายการเกณฑ์การจับคู่และค่าเริ่มต้น |
| `POST` | `/api/upload` | อัปโหลดไฟล์ (multipart: `file`, `options`) แล้วประมวลผล |
| `POST` | `/api/jobs/:id/rematch` | จับคู่ใหม่ด้วยเกณฑ์ที่ต่างไป |
| `GET` | `/api/jobs/:id` | ดึงผลลัพธ์เดิม |
| `GET` | `/api/jobs/:id/export?format=xlsx\|pdf` | ดาวน์โหลดรายงาน |
| `GET` | `/api/history` | ประวัติการประมวลผลจากฐานข้อมูล |
